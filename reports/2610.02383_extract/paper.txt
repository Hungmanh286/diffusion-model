Looped Transformers apply the same layers several times per token, adding compute to improve quality without more parameters. Each recursion, however, writes
its own key-value cache, so memory still grows with compute. Inference-time
techniques can shrink this cache at a cost in quality. We pretrain looped language
models to share memory: only the first recursion writes a cache, and later recursions read it while keeping a short window of their own. Surprisingly, we find
that sharing memory does not cost quality and instead improves it. At 150M–1B
parameters, our Looped Prediction Transformer (LPT) and its hybrid variant set a
new quality–memory frontier for looped models: with five recursions, the hybrid
lowers validation perplexity on FineWeb-Edu by 1.12–1.82 relative to a same-size
standard Transformer while using 76–79% less context memory. Through an extensive analysis, we investigate why memory sharing helps. Shared and local memory
develop different representations, and later recursions attend mostly to the shared
memory, which also acts as a gradient highway to the first recursion.

I NTRODUCTION

Looped Transformers (LT) repeatedly apply the same layers several times before predicting the next
token, adding computation without adding parameters (Dehghani et al., 2019; Zhu et al., 2025).
In principle, they trade time for memory, matching the compute of a larger model with far fewer
parameters. In standard formulations, however, context memory still grows with recursion depth, as
each iteration keeps a separate key-value (KV) cache (Geiping et al., 2025; Zhu et al., 2025). At
long contexts, this context memory can grow larger than the weights memory itself, undoing the very
reason to use a looped model.
Sharing caches across recursions during decoding can save substantial memory with little quality
loss (Geiping et al., 2025; Zhu et al., 2025). So far, this reuse has been studied mainly as a way to
save memory. Yet it also shows that memory written by one recursion can serve the others, even in
models never trained to share it. This raises a question: if sharing can work untrained, what can it do
when models are trained for it? To answer it, we train looped models with memory sharing from the
start, investigating it as an architectural inductive bias.
We study a simple recipe for Memory Sharing in looped Transformers (Figure 1, left). At each
full-attention layer, later recursions attend to both their own KV entries and the cache written by that
layer in the first recursion, within the same attention operation. To further save memory, we truncate
the cache of every recursion after the first to a short sliding window. The resulting Looped Prediction
Transformer (LPT) keeps LT’s sequential recurrence and uses context memory close to a standard
(non-looped) Transformer’s. Applied to the full-attention layers of a hybrid looped Transformer (Deng
et al., 2026), the same rule yields the Hybrid Looped Prediction Transformer (H - LPT). We pretrain
all models from scratch at 150M to 1B parameters. Because later recursions give up most of their
own memory, one would expect Memory Sharing to cost some quality, as untrained sharing does.
Surprisingly, Memory Sharing improves quality over full-cache LT even when each later recursion’s
own cache covers less than 2% of the context. Its advantage grows with depth: LT stops improving
in perplexity after three recursions, while LPT improves through five. Across sizes, LPT lowers
validation perplexity by up to 1.09 nats and raises downstream accuracy by up to 4.8 percentage
points over a matched-depth LT, with up to 4.7× less context memory and nearly the same inference
FLOPs. Sharing also improves the hybrid baseline: at five recursions, H - LPT outperforms a same-size
standard Transformer in both language modeling and downstream accuracy while using 76–79% less
context memory, moving the quality–memory frontier for looped models (Figure 2).
These results raise a further question: why does memory sharing improve quality? We find that later
recursions rely heavily on the shared memory. LPT outperforms LT at every window size, even when
later recursions keep no cache of their own, and later recursions attend mostly to shared memory
even when their own cache covers the full context. Shared and local memory also develop distinct
key representations, suggesting that they serve different purposes. Reading shared memory sends
gradients directly to the first recursion, helping it learn what to store. This gradient highway bypasses
the intermediate recursions: in LT, the magnitude of the gradient reaching the first recursion falls
sharply with depth, while LPT recovers much of it through the shared memory. When we block this
path, the model still reads shared memory but no longer matches LPT’s quality and stability.

L OOPING WITH S HARED M EMORY

We study Memory Sharing, in which later recursions read the memory written by the first recursion,
as an inductive bias for looped models. The first recursion runs as in LT and writes a full-context
cache C (1) at each layer, and every later recursion attends to this cache together with its own KV
entries, using a single softmax.
To also keep looping memory-efficient, we restrict each later recursion’s own cache to a short window.
The first recursion therefore acts as a memory phase that builds the model’s only full-context memory,
while later recursions use it to refine the prediction. We refer to the first recursion as the state
recursion and to the later ones as prediction recursions, and call the resulting model the Looped
Prediction Transformer (LPT; Figure 1). Like LT, LPT applies the same L-layer stack R times and
passes the final output to the language-modeling head (Equation 1).

R ESULTS

Memory Sharing Improves Quality Restricting the memory written by later recursions could
hurt prediction. Surprisingly, our Memory Sharing approach improves quality. At matched size
and recursion count, LPT lowers validation perplexity by 0.38–1.09 and raises accuracy by 0.4–4.8
percentage points over LT, with 2.0–4.7× less KV memory and under 1% more FLOPs (Table 1).
Measured on an H100, the memory savings are the same, so LPT fits 2.0–4.8× as many sequences
in a batch as LT (Appendix F). The perplexity gain grows with recursion count (Table 1): LT stops
improving beyond three recursions at every size, while LPT continues to improve through five. At
comparable cache sizes, LPT also reaches lower perplexity than PLT’s parallel formulation.

When it comes to hybrid variants, H - LPT keeps this memory at 0.18–0.24× STD’s across recursion
counts, while LT 2’s remaining full-attention caches still grow with depth, approaching STD’s context
memory at five recursions. Despite these 2–4× memory gains, H - LPT matches or outperforms LT 2
in terms of quality at every recursion count. At five recursions, it lowers perplexity by 0.09–0.15
and raises accuracy by 0.8–1.2 points over LT 2, with 4.1–4.2× less context memory and about 0.1%
more inference FLOPs.
Incidentally, we note that for low recursion counts, the hybrid LT 2 improves on LT while using less
memory and compute. A factor that could explain this gap – and the instability of LT – is Ouro’s
normalization, which we use for both LT and LPT. In Appendix C, we explore other normalizations
that make LT more robust, but none of these variants matches LPT.
More Quality from the Same Parameters Both memory-sharing models improve on STD with
little additional memory, or much less for H - LPT (Figure 2). At five recursions, LPT lowers perplexity
by 1.03–1.92 and raises accuracy by 3.4–5.7 points with 6.25% more context memory. H - LPT lowers
perplexity by 1.12–1.82 and raises accuracy by 3.1–5.6 points with 76–79% less memory. This
smaller cache lets H - LPT fit 3.6–5.0× as many sequences as STD on one GPU. With three to five
recursions, H - LPT lowers perplexity by 0.94–1.82 while beating or staying close to STD’s throughput
(1.4–1.5× at three, 81–88% at five, Appendix F). Both models’ accuracy gains grow from two to
five recursions at every size. LPT also outperforms LOOPIE and DEEPSTD, neither of which improves
consistently with depth.
Takeaway 1. Through Memory Sharing, LPT and especially H - LPT improves the quality–memory
frontier for looped models (Figure 2).

W HY M EMORY S HARING H ELPS

We use S- and M-size models with two, three, and five recursions to study why this inductive bias
improves quality (Appendix D).
Memory Sharing Stabilizes Deep Recursion We compare final and adaptive loss in LT and LPT
(Figure 3). Without intermediate supervision, adding recursions consistently worsens LT’s perplexity,
and the model collapses to unigram-level loss at five recursions. LPT stays stable, and final loss
lowers its perplexity by 0.16–0.50 compared with adaptive loss. Its intermediate recursions can refine
the hidden state without having to predict early.
Takeaway 2. LPT stays stable and trains best with final loss.

Prediction Recursion Needs Local Memory We train LPT with prediction windows ranging from
ω = 0 to the full context of 4,096 tokens (Figure 4). LPT outperforms LT at every window size,
across both sizes and all tested depths. This includes ω = 0, where prediction recursions keep no
local history and read shared memory alongside only their current KV entry. At the other extreme,
ω = 4,096, LT and LPT differ only in access to shared memory. LPT still lowers perplexity by
0.24–1.15 relative to LT with the better of its two training objectives at each depth, close to the
0.32–1.09 gain at ω = 64. Overall, window size has a modest effect on quality, and what really
matters is the access to the shared memory. To balance quality and efficiency, we adopt ω = 64 as
the default for our memory sharing models.
Takeaway 3. Shared memory improves quality across prediction-window sizes, even when later
recursions keep no local history.

Shared and Local Memory Develop Different Representations Shared keys serve every later
recursion, whereas local keys serve only the recursion that writes them. To see whether these roles
are reflected in their representations, we compare S-size LT and LPT with three recursions, both
trained with final loss, the only tested setting with at least three recursions where LT trains with
final loss without a substantial drop in quality (Figure 3). We evaluate both models on the same
4,096-token validation sequence and extract queries and keys before rotary encoding. We concatenate
the attention heads and fit principal component analysis (PCA) jointly to queries and keys across
tokens and recursions per model and layer (Appendix D).
Shared and local keys consistently form distinct clusters in LPT, whereas keys from different recursions overlap more in LT (Figure 6). In Appendix D, we show similar separation in LPT across S
and M at three and five recursions (Figure 10). We also show that with full prediction caches, the
clusters overlap more but still remain distinguishable, even though shared and local keys cover the
same positions (Figure 9). Prior work attributes the small cost of cache reuse to the similarity of
keys and values across recursions (Bae et al., 2025), as we see in LT. With Memory Sharing, shared
and local keys are instead clearly different. This shows that representation similarity across layers
is not a necessary condition for effective memory sharing. This also fits the freedom that final loss
gives: recursions need not all produce prediction-ready states, so the first can specialize in building
memory and the later ones in using it. This specialization may help explain the quality gains, similar
to how Monea et al. (2026) show that Transformers benefit from assigning memory construction and
next-token prediction to separate residual streams.
Takeaway 5. Shared and local memory diverge in their local representations, so sharing is not
reliant on recursions writing similar memories.

Shared Memory Is a Gradient Highway Reading shared memory gives the final loss a direct
gradient path to the first recursion, bypassing the intermediate recursions. We evaluate the STD, LT,
and LPT models of Table 1 on the same 32 validation sequences of 4,096 tokens and backpropagate
the final loss from 32 fixed positions in each. We measure each recursion’s contribution to the gradient
on the Transformer block weights, and split the first recursion’s contribution into its hidden-state and
shared-KV paths by repeating the backward pass with shared KV detached (Appendix D).
In LT, the first-recursion gradient norm falls sharply with depth. LPT recovers much of the signal
magnitude relative to the single-pass STD reference, with a much smaller decline as depth increases
(Figure 7). At five recursions, most of this gradient comes through the shared KV cache. The same
holds for LPT with adaptive loss or full prediction caches (Figure 12).
To test whether this highway helps learning, we train LPT from scratch with shared KV detached at
later reads. The forward computation and hidden-state gradient path are unchanged. Perplexity rises
in both sizes and at every depth, and deeper detached models often fail to train (Figure 8).
Takeaway 6. The memory sharing mechanism creates a gradient highway from the final loss to
the first recursion that facilitates learning.

The first layers write one cache once, and the remaining layers only read it (Sun et al., 2024; 2026;
DeepSeek-AI, 2026; Capps, 2026). Instead, LPT decouples memory from prediction across the
recursions of a looped Transformer: the first recursion writes the model’s only full-context memory,
and every later recursion reads it while it predicts, keeping just a short window of its own. Looped
models thus offer a third place for the split, with no extra stream or layer, and our analysis finds
evidence that the recursions learn these roles (Section 6).
Looped Transformers and Memory Sharing Looped Transformers apply the same layers several
times (Dehghani et al., 2019; Geiping et al., 2025; Zhu et al., 2025), and recent work differs in which
layers repeat and how recursions connect (Gao et al., 2026; Wang et al., 2026a; Huang et al., 2026;
Mozer et al., 2026; Wang et al., 2026b; Deng et al., 2026). In standard formulations, each recursion
writes its own KV cache, so context memory grows with depth (Geiping et al., 2025; Zhu et al.,
2025). Sharing a cache across recursions, like sharing it across layers (Brandon et al., 2024), has been
studied as a way to save memory. Without retraining, Huginn (Geiping et al., 2025) reuses caches
cyclically with little quality loss, and Ouro (Zhu et al., 2025) can keep only the final or an averaged
cache. Keeping only the first recursion’s cache sharply reduces Ouro’s quality, which suggests that
shared memory has to be trained. Trained variants reuse the first recursion’s keys and values at a
slight cost in quality (Bae et al., 2025), compute them once in a separate prelude (Capps, 2026),
or learn gated or compressed caches (Vendrell et al., 2026; O’Neill & Reid, 2026). PLT (Wu et al.,
2025) has the closest design to ours, although it focuses on parallelizing recursions. It shares the
first recursion’s cache with gated local caches and runs recursions in parallel, while LPT keeps them
sequential and reads both caches in one softmax. We find that LPT performs better. All of these treat
sharing as a cost to contain. We instead treat it as an inductive bias that separates memory from
prediction and show that it improves quality (Section 5 and Section 6).

D ISCUSSION

We investigate memory sharing as an architectural inductive bias for looped models, and find that
it not only cuts context memory but also improves quality in both full attention and hybrid models.
Our Memory Sharing LPT models achieve consistently better perplexity and downstream accuracy
than their usual looped counterparts, while matching the KV cache memory of a standard non-looped
model. Our analyses suggest that sharing helps recursions learn different roles. The first recursion
builds memory that later recursions use to refine the prediction. Those reads also give the final loss a
direct gradient path to the first recursion. The different representations of shared and local memory
support this division of roles, and cutting this gradient path hurts learning. Shared memory changes
how later recursions read information and how the first recursion learns to write it.
Overall, our findings suggest that shared memory is a useful inductive bias for looped models, helping
them make better use of computation within a limited memory budget.
Limitations & Future work Like other looped Transformers, LPT is not compute-optimal: it
trades time for quality, but unlike LT, its memory barely grows with depth. At five recursions it
costs 4.3–4.8× the decoding FLOPs of STD, about the same as LT, and it spends the same number
of recursions on every token. Choosing that number per token is future work. All our comparisons
are parameter-matched, including DEEPSTD, and we do not train a standard Transformer matched
in decoding FLOPs instead, which at five recursions would have several times the parameters. We
train up to 1B parameters on one corpus with 4,096-token contexts and do not test long-context tasks
or, given our limited pretraining, very advanced tasks. Our analyses use S and M models, since
not every configuration they need was trained at L, and only the detach ablation looks at training
dynamics. Both the stability and memory improvements of LPT are promising for effectively scaling
looped models to higher recursion counts. More sophisticated Memory Sharing approaches could
also be explored in future work, such as increasing the number of state recursions or alternating state
recursions and prediction recursions.

LT and LPT use Ouro’s normalization and recurrent transition (Zhu et al., 2025). LT 2 and H - LPT
use the Full+GDN layer pattern and gating setup of Deng et al. (2026), with one full-attention layer
per five layers. The full-attention layers read the complete causal context in LT 2. In H - LPT, later
recursions read the first recursion’s full-context cache and their own local prediction window, as in
Equation 3.
PLT uses the same block, recurrent, and readout normalization as LT and LPT. Its recurrent transition
adds the input embedding to the previous recursion’s normalized output shifted by one token.

Attention Implementation During training, each prediction recursion concatenates its keys and
values with the shared keys and values along the sequence dimension, separately at each full-attention
layer. A block mask implements Equation 3, allowing full causal attention over shared entries and
causal sliding-window attention over local entries. FlexAttention (Dong et al., 2025) skips fully
masked blocks.
Data Processing We tokenize with the GPT-2 tokenizer (Radford et al., 2019) and pack documents
into 4,096-token sequences, inserting an end-of-sequence token between documents. Attention is
masked across document boundaries, and boundary tokens are excluded from the language-modeling
loss.
Optimization We use AdamW with β1 = 0.9, β2 = 0.95, weight decay 0.1, and gradient clipping
at 1.0. The global batch contains 96 sequences of 4,096 tokens, and training uses bfloat16 mixed
precision. For L-size models, AdamW optimizer state is sharded across DDP ranks (ZeRO-1). The
learning rate increases linearly to 6 × 10−4 over the first 50M tokens, stays constant, then decreases
linearly to 6 × 10−5 over the final 10% of training. These are nanoGPT’s default optimizer settings,
used unchanged for every model, size, and objective: we did not tune the learning rate or the warmup
for any model, and we did not test whether a lower peak learning rate or a longer warmup changes
how final-loss LT trains at depth (Figure 3).
For adaptive loss, we use Ouro’s adaptive-exit objective (Zhu et al., 2025). A learned per-token
halting distribution weights the losses across recursions, with a KL regularization weight of 0.1. Final
loss applies the language-modeling loss only at the last recursion.

D ECODING S PEED AND M EMORY ON A GPU

We test whether the analytic memory savings translate into larger batches and higher decoding
throughput on a GPU. A smaller cache lets more sequences share a GPU, which can raise throughput (Brandon et al., 2024; Sun et al., 2024). As O’Neill & Reid (2026) do for a looped model, we
measure the largest batch that fits at a fixed context and the throughput at that batch.
Setup We decode on one NVIDIA H100 with 80 GB of memory, in bf16, at a 4,096-token
context: each step generates one token per sequence from a cache already filled to 4,068 tokens. All
models share one decoding implementation in PyTorch: a preallocated cache per attention layer,
FlexAttention (Dong et al., 2025) for attention, and CUDA graphs that replay a whole decoding
step, all recursions and layers included. A later recursion of LPT or H - LPT attends to its shared and
local caches in one softmax, which we compute by merging the two FlexAttention outputs by their
log-sum-exp. Gated DeltaNet layers update their recurrent state one token at a time, with the kernels
of flash-linear-attention (Yang & Zhang, 2024). STD runs the same code with one recursion, and
LT runs all its recursions, without early exit. Weights are random, since speed and memory do not
depend on them. On the same GPU, decoding reproduces the full forward pass to bf16 precision.
The maximum batch is the largest batch whose decoding steps run without running out of memory,
and we measure throughput at this batch, or at 95% of it when the CUDA graph does not fit. These
measurements come from one research implementation, not an optimized serving engine, which
would change the absolute speeds. Every model runs the same code, so the comparison holds within
this implementation.
Capacity Table 8 shows that the analytic savings carry over to the GPU. LPT’s cache per sequence
is at most 6.25% larger than STD’s, so it fits 93–98% of STD’s batch. LT’s cache grows with depth, so
LPT fits 2.0, 2.9, and 4.7–4.8 times as many sequences as LT at two, three, and five recursions. H - LPT
holds 20–27% of STD’s cache and fits 3.6–5.0 times as many sequences as STD, and 1.8–3.8 times as
many as LT 2. The hybrids’ measured caches are 3–17% larger than the analytic values in Table 1,
because the kernel keeps the recurrent state in fp32 and we also count the short-convolution windows.
Speed The larger batches raise LPT’s peak throughput above LT’s by 7–91%, most at L with five
recursions, where LT fits only 21 sequences. At equal batch, LPT is 3–8% slower than LT, since each
later recursion still reads the whole shared cache, and its own window too. As Brandon et al. (2024)
note for sharing across layers, a shared cache saves memory, not the time to read it. Both looped
models pay for depth in time: at batch 1, a decoding step of LT takes about 2.3, 3.4, and 5.7 times
as long as STD’s at two, three, and five recursions, and LPT’s takes 8–12% longer than LT’s. The
hybrids read a full-context cache in only one layer of five, so they decode faster. At its maximum
batch, H - LPT generates 2.1–2.2 times as many tokens per second as STD with two recursions, 1.4–1.5
times with three, and 0.8–0.9 times with five, and it is 2–3% slower than LT 2 at equal batch.
Throughput and Quality Figure 17 plots quality against throughput. At every size and recursion
count, LPT has higher throughput, lower perplexity, and higher accuracy than LT, and H - LPT has
higher throughput and lower perplexity than LT 2. Against STD, H - LPT lowers perplexity by 0.94–1.44
with three recursions while decoding 1.4–1.5 times as many tokens per second, and by 1.12–1.82
with five, at 81–88% of STD’s throughput.
