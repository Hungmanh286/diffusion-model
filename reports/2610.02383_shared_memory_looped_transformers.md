## 1. Bài toán & Khoảng trống nghiên cứu (Problem)

### Bài toán
Looped Transformers (LT) áp dụng cùng một stack layer $R$ lần cho mỗi token, cho phép tăng compute mà không tăng số lượng parameter. Tuy nhiên, mỗi recursion ghi một KV cache riêng, khiến **context memory tăng tuyến tính** theo số recursion $R$, dù parameter count cố định. Tại context dài, context memory có thể vượt qua weights memory, phá hủy chính lý do sử dụng looped model.

- **Input:** Chuỗi token đầu vào
- **Output:** Next-token prediction (language modeling)
- **Setting:** Pretrained looped language models, decoder-only, 150M–1B parameters

### Khoảng trống nghiên cứu
- Các kỹ thuật giảm KV cache ở inference time (reuse cyclically, giữ cache cuối/trung bình) đều **làm giảm chất lượng**, đặc biệt khi chỉ giữ cache của recursion đầu tiên (Ouro giảm mạnh chất lượng).
- Các nghiên cứu trước coi memory sharing chỉ là biện pháp tiết kiệm bộ nhớ, chấp nhận quality loss. Chưa có ai nghiên cứu memory sharing **như một inductive bias kiến trúc** — tức train model từ đầu với sharing.
- LT gặp vấn đề ổn định khi tăng recursion depth: perplexity không cải thiện sau 3 recursions, thậm chí diverge ở 5 recursions với final loss.

---

## 2. Key Insight

Shared memory không chỉ tiết kiệm bộ nhớ mà thực sự **cải thiện chất lượng**: khi train looped Transformer từ đầu với memory sharing — chỉ recursion đầu ghi full-context KV cache, các recursion sau đọc cache đó cùng một sliding window ngắn — các recursion phát triển các vai trò khác nhau (state vs. prediction), và shared memory tạo ra một **gradient highway** trực tiếp từ final loss đến recursion đầu, giúp model học tốt hơn và ổn định hơn khi tăng depth.

---

## 3. Contributions

1. **Đề xuất Looped Prediction Transformer (LPT) và hybrid variant H-LPT**: train looped models từ đầu với memory sharing — recursion đầu (state recursion) ghi full-context cache, các recursion sau (prediction recursions) đọc shared cache kết hợp sliding window ngắn ($\omega = 64$).

2. **Chứng minh memory sharing cải thiện chất lượng**: LPT giảm perplexity 0.38–1.09 và tăng accuracy 0.4–4.8 điểm so với LT, đồng thời giảm 2.0–4.7× KV memory. H-LPT tại 5 recursions hạ perplexity 1.12–1.82 so với STD và giảm 76–79% context memory.

3. **Phân tích sâu tại sao memory sharing giúp ích**: 
   - Shared và local memory phát triển representation khác biệt
   - Prediction recursions attend chủ yếu vào shared memory (57–80%)
   - Shared memory hoạt động như gradient highway đến recursion đầu
   - Cắt gradient path này làm giảm quality và stability

## 4. Phương pháp chi tiết (Detailed Methodology)

### 4.1 Looped Transformer Baseline (LT)

Một stack $M_L = T_\theta^{(L)} \circ \cdots \circ T_\theta^{(1)}$ gồm $L$ Transformer blocks được áp dụng $R$ lần:

$$h_{in}^{(1)} = \text{emb}(x)$$
$$h^{(t)} = M_L(h_{in}^{(t)}), \quad t = 1, \ldots, R$$
$$h_{in}^{(t+1)} = N_{rec}(h^{(t)})$$
$$\text{logits}^{(t)} = \text{lm\_head}(N_{out}(h^{(t)}))$$

- $N_{rec}$, $N_{out}$: hai RMSNorm riêng biệt — recurrent norm chuẩn bị input cho recursion tiếp, readout norm cho language-modeling head.
- Effective depth: $L \cdot R$, với parameters chỉ của 1 stack $L$-layer.
- Mỗi recursion ghi KV cache riêng: $A_{LT}^{(t)}(i) = C_{\leq i}^{(t)}$

**Vấn đề:** KV cache $M_{KV}^{LT} = L \cdot R \cdot T$ tăng tuyến tính theo $R$.

### 4.2 Looped Prediction Transformer (LPT)

**Thiết kế cốt lõi (Equation 3):**

$$A_{LPT}^{(t)}(i) = \begin{cases} C_{\leq i}^{(1)}, & t = 1 \\ C_{\leq i}^{(1)} \cup C_{[i-\omega, i]}^{(t)}, & t = 2, \ldots, R \end{cases}$$

- **State recursion** ($t=1$): chạy như LT bình thường, ghi full-context cache $C^{(1)}$.
- **Prediction recursions** ($t \geq 2$): đọc shared cache $C^{(1)}$ kết hợp sliding window $\omega$ token gần nhất của chính nó, trong **cùng một softmax**.
- Window mặc định $\omega = 64$ (chiếm ~1.6% context length 4,096).

**KV cache size:**
$$M_{KV}^{LPT} = L[T + (R-1)\omega]$$

So với LT ($L \cdot R \cdot T$), giảm $\frac{RT}{T + (R-1)\omega}$ lần. Ví dụ: $T=4096$, $\omega=64$, $R=5$ → giảm 4.7×.

**FLOPs overhead:** Prediction recursions phải đọc thêm local window, nhưng chỉ tăng $(R-1)\omega / (RT) = 1.25\%$ attended entries.

### 4.3 Hybrid Variant (H-LPT)

Áp dụng memory sharing cho hybrid looped Transformer (LT²):
- **Linear-attention layers (Gated DeltaNet):** Mỗi recursion giữ recurrent state riêng (nhỏ, kích thước cố định).
- **Full-attention layers (1 trong 5 layers):** Áp dụng Equation 3 như LPT.

Kết quả: context memory chỉ 0.18–0.24× so với STD qua mọi recursion count.

### 4.4 Attention Implementation

- **Training:** FlexAttention block mask trên concatenated shared + local entries. Skips fully masked blocks → mỗi query chỉ attend shared prefix + $\omega$ window entries.
- **Inference:** Mỗi prediction recursion giữ sliding buffer $\leq \omega$ entries/layer. Current entry tham gia attention trước khi vào buffer.

## 5. Training & Loss Objectives

### Dữ liệu
- **Dataset:** FineWeb-Edu
- **Token budget:** 20B tokens cho S (150M) và M (450M), 50B tokens cho L (1B) — khoảng 2–7× Chinchilla compute-optimal.
- **Tokenizer:** GPT-2
- **Context length:** 4,096 tokens, packing documents với EOS token, masking attention across document boundaries.

### Hai training objectives

1. **Final loss:** NLL chỉ tại recursion cuối cùng. Cho phép intermediate recursions tự do refine hidden state mà không cần predict sớm.
2. **Adaptive loss (Ouro):** Weighted per-recursion NLLs với learned per-token halting distribution + KL regularization (weight 0.1).

**Phát hiện quan trọng:** LPT train tốt nhất với **final loss** (giảm 0.16–0.50 PPL so với adaptive loss), trong khi LT **cần** adaptive loss để không diverge ở depth ≥ 5. Đây là một bằng chứng mạnh cho memory sharing stabilize training.

### Optimization
- AdamW: $\beta_1 = 0.9$, $\beta_2 = 0.95$, weight decay 0.1, gradient clipping 1.0
- Batch: 96 sequences × 4,096 tokens
- Mixed precision: bfloat16
- Learning rate: linear warmup đến $6 \times 10^{-4}$ qua 50M tokens → constant → linear decay đến $6 \times 10^{-5}$ qua 10% cuối training
- L-size: ZeRO-1 sharding optimizer state
- **Không tune hyperparameter** (LR, warmup) cho bất kỳ model nào — dùng nanoGPT defaults.

### Architecture Configs

| | S | M | L |
|---|---|---|---|
| Layers ($L$) | 12 | 24 | 36 |
| Hidden size ($d$) | 768 | 1,024 | 1,280 |
| Heads | 12 | 16 | 20 |
| FFN size | 3,072 | 4,096 | 5,120 |
| Parameters | 151.9M | 454.2M | 1.01B |

## 6. Inference & Hiệu năng GPU (không có guidance)

### Decoding
- Mỗi prediction recursion giữ sliding buffer $\leq \omega$ entries per layer.
- Current entry tham gia attention trước khi vào buffer.
- Không có early exit — mọi token qua đủ $R$ recursions.

### GPU Implementation
- PyTorch + CUDA graphs replay toàn bộ decoding step (tất cả recursions và layers).
- Later recursions: merge shared + local FlexAttention outputs bằng log-sum-exp.
- Gated DeltaNet: flash-linear-attention kernels.
- bf16 precision.

### Memory Capacity trên H100 (80GB)

Với 5 recursions, context 4,096:
- **LPT** fits 2.0–4.8× nhiều sequences hơn LT
- **H-LPT** fits 3.6–5.0× nhiều sequences hơn STD

### Throughput
- H-LPT với 3 recursions: **1.4–1.5× throughput** so với STD, đồng thời hạ PPL 0.94–1.44.
- H-LPT với 5 recursions: **81–88% throughput** STD, hạ PPL 1.12–1.82.
- LPT chậm hơn LT 3–8% ở equal batch (vì vẫn đọc full shared cache + window), nhưng peak throughput cao hơn 7–91% nhờ batch size lớn hơn.

Paper không có guidance/steering — đây là pure language modeling.

## 7. Kết quả thực nghiệm (Experimental Results)

### Baselines
- **STD:** Standard Transformer (1 pass)
- **DEEPSTD:** Deeper, narrower Transformer matched effective depth & parameters
- **LT:** Looped Transformer (Ouro formulation, adaptive loss)
- **PLT:** Parallel Loop Transformer (gated dual attention)
- **LOOPIE:** Repeats each layer before advancing
- **LT²:** Hybrid looped (Gated DeltaNet + full attention, 1/5 ratio)

### Evaluation
- **Perplexity:** 10M held-out FineWeb-Edu tokens
- **Downstream:** Mean zero-shot accuracy trên ARC-Easy, HellaSwag, PIQA, SciQ, LAMBADA (LM Evaluation Harness)
- **Efficiency:** Context memory & decoding FLOPs tại 4,096-token context, relative to STD

### Kết quả chính (Table 1)

**LPT vs. LT** (cùng size, cùng recursion count):
- Giảm PPL: 0.38–1.09
- Tăng accuracy: 0.4–4.8 điểm phần trăm
- Giảm KV memory: 2.0–4.7×
- FLOPs thêm: < 1%

**H-LPT vs. STD** (5 recursions):
- Giảm PPL: 1.12–1.82
- Tăng accuracy: 3.1–5.6 điểm phần trăm
- Giảm context memory: 76–79%

**H-LPT vs. LT²** (5 recursions):
- Giảm PPL: 0.09–0.15
- Tăng accuracy: 0.8–1.2 điểm
- Giảm context memory: 4.1–4.2×

**Scaling with depth:**
- LT ngừng cải thiện PPL sau 3 recursions ở mọi size.
- LPT tiếp tục cải thiện qua 5 recursions.
- H-LPT tiếp tục cải thiện qua cả 9 recursions.

### Kết quả cụ thể tại L (1B params, 5 recursions):
| Model | PPL | Acc (%) | KV (×STD) |
|---|---|---|---|
| STD | 11.35 | 62.5 | 1.00× |
| LT | 11.39 | 63.4 | 5.00× |
| LPT | 10.32 | 68.2 | 1.06× |
| LT² | 10.32 | 67.3 | 1.01× |
| H-LPT | 10.23 | 68.1 | 0.24× |

### Kết quả định tính (phân tích Section 6)

**Attention patterns:** Shared memory nhận 57–71% attention mass ở prediction recursions sớm, tăng lên 73–80% ở recursion cuối.

**Key representation PCA:** Shared keys và local keys tạo thành clusters riêng biệt trong LPT, trong khi keys từ các recursions khác nhau overlap nhiều trong LT.

## 8. Ablation Study & Phân tích

### 8.1 Training Objective (Figure 3)
- **LT + final loss:** Diverge hoặc degrade ở 5 recursions (unigram-level perplexity ~2,040).
- **LPT + final loss:** Ổn định qua mọi depth, PPL tốt hơn adaptive loss 0.16–0.50.
- → Memory sharing stabilize deep recursion.

### 8.2 Prediction Window Size (Figure 4)
- LPT outperforms LT **ở mọi $\omega$**, kể cả $\omega = 0$ (chỉ current entry, không giữ local history).
- Tại $\omega = 4,096$ (full context — giống LT về cache size): LPT vẫn giảm PPL 0.24–1.15 so với LT → chứng tỏ **access to shared memory** là yếu tố quan trọng, không phải kích thước window.
- Window size có ảnh hưởng khiêm tốn lên quality; $\omega = 64$ cân bằng tốt quality-efficiency.

### 8.3 Attention to Shared Memory (Figure 5)
- Prediction recursions attend chủ yếu vào shared memory (57–80%).
- Tỷ lệ tăng dần qua các recursion gần prediction cuối.
- Kết quả consistent với full prediction caches và adaptive loss.

### 8.4 Key Representation Separation (Figure 6)
- PCA cho thấy shared keys và local keys tạo clusters riêng biệt trong LPT.
- Trong LT, keys từ các recursions khác nhau overlap nhiều.
- → Representation similarity **không phải** điều kiện cần cho effective memory sharing. Shared và local memory serve các mục đích khác nhau.

### 8.5 Gradient Highway (Figure 7)
- Trong LT, gradient norm của recursion đầu giảm mạnh theo depth.
- Trong LPT, shared KV cache tạo đường gradient trực tiếp, phục hồi phần lớn signal magnitude.
- Tại 5 recursions, phần lớn gradient đến recursion đầu đi qua shared KV path.

### 8.6 Gradient Detachment Ablation (Figure 8, Table 6)
- Detach shared KV tại các later reads → giữ nguyên forward computation, chỉ cắt gradient path.
- Kết quả: PPL tăng ở mọi configuration. Deep detached models thường fail to train.
- Ví dụ: LPT (S, R=5) PPL = 14.91, LPT detached = 33.21, LT final loss = 2,040.

### 8.7 Normalization Comparison (Appendix C, Table 5)
- 6 normalization variants cho LT với final loss: Pre-norm only, Sandwich only, Input norm, Update norm, KEEL, Ouro.
- LPT với Ouro normalization **vẫn tốt hơn** best LT (0.06–0.43 PPL tại M, 0.31–0.37 tại S).
- Comparison này **thiên lợi cho LT** (best of 6 norms vs. single norm cho LPT).

### 8.8 Nine Recursions (Appendix E)
- LPT: cải thiện nhỏ ở S, giảm quality ở M và L.
- H-LPT: tiếp tục cải thiện ở mọi size (PPL thấp nhất tại 9 recursions).
- LT và PLT: worsen perplexity ở mọi size.

## 10. Phản biện & Giả định ngầm (Critical Analysis)

### 10.1 Giả định ngầm

1. **Recursion đầu tiên là tối ưu cho state recursion:** Paper mặc nhiên chọn recursion đầu làm memory writer duy nhất. Không khảo sát: (a) nhiều state recursions, (b) xen kẽ state/prediction, (c) later recursion cũng contribute vào shared memory. Tác giả nhận ra điều này trong Limitations nhưng không thử.

2. **Window size cố định cho mọi layer và recursion:** $\omega = 64$ được dùng uniform. Có thể các layer khác nhau hoặc recursion khác nhau cần window size khác nhau.

3. **Softmax attention là cách kết hợp tối ưu:** Shared và local entries được attend trong cùng một softmax. PLT dùng gated dual attention — paper so sánh nhưng không khám phá các cách kết hợp khác.

4. **Single corpus, single tokenizer:** Mọi kết luận dựa trên FineWeb-Edu với GPT-2 tokenizer. Generalization sang các domain/tokenizer khác chưa kiểm chứng.

5. **Gradient highway là cơ chế chính:** Paper chỉ ra correlation (gradient magnitude restoration) và intervention (detachment hurts), nhưng cơ chế chính xác tại sao gradient highway dẫn đến better representations chưa được giải thích rõ.

### 10.2 Hạn chế

**Do tác giả tự nêu:**
- LPT **không compute-optimal**: 4.3–4.8× decoding FLOPs so với STD tại 5 recursions (giống LT).
- Không so sánh với FLOPs-matched STD (nhiều parameters hơn).
- Mọi token dùng cùng số recursions — chưa có adaptive computation.
- Chỉ train đến 1B params, 4,096 context, trên 1 corpus.
- Không test long-context tasks hoặc advanced tasks.
- Phân tích chỉ ở S và M, không phải L.
- Chỉ detach ablation nhìn vào training dynamics.

**Quan sát thêm:**
- **Không so sánh với non-looped efficient attention** (Linear Attention standalone, Mamba, RWKV) — chỉ so sánh trong framework looped.
- **9 recursions cho kết quả mixed**: LPT giảm quality ở M và L, cho thấy memory sharing không giải quyết hoàn toàn scalability theo depth.
- **Perplexity-accuracy gap**: H-LPT đôi khi có PPL tốt hơn LPT nhưng accuracy không tương xứng (Table 1, L at R=5: H-LPT PPL 10.23 vs LPT 10.32, nhưng Acc 68.1 vs 68.2). Metric alignment chưa rõ ràng.
- **Latency overhead**: Batch-1 latency tăng 2.3–5.7× so với STD — nghiêm trọng cho real-time applications.

### 10.3 Tính công bằng thực nghiệm

**Điểm mạnh:**
- Tất cả models dùng cùng seed, data order, optimizer settings (nanoGPT defaults, không tune).
- Parameter-matched comparisons nhất quán.
- Statistical tests (paired t-test) với 4 seeds tại S.
- Normalization ablation (6 variants) để loại trừ normalization là confound.

**Điểm yếu:**
- **LT dùng adaptive loss** trong main comparison, LPT dùng final loss → khác training objective. Tuy nhiên, paper justify bằng cách cho thấy LT diverge với final loss, và thử cả adaptive loss cho LPT (LPT vẫn tốt hơn).
- **Hyperparameter search budget không đồng đều**: LPT giữ Ouro normalization, LT được thử 6 norms. Tuy nhiên hướng bias **có lợi cho LT** (best of 6 vs. 1), và LPT vẫn thắng.
- **PLT comparison**: PLT dùng cùng normalization/recurrence setup nhưng thiết kế gốc có thể tối ưu cho settings khác.
- **Seed check chỉ ở S**: Costs prohibitive, nhưng M và L conclusions dựa trên single run.

## 11. Hướng mở rộng & Ứng dụng

### Cơ hội cải tiến
1. **Adaptive recursion count per token:** Tokens dễ dùng ít recursions, tokens khó dùng nhiều — kết hợp với adaptive computation (early exit, halting).
2. **Multiple state recursions hoặc alternating pattern:** Ví dụ state → predict → state → predict, cho phép refine shared memory.
3. **Learned window size:** Per-layer hoặc per-recursion adaptive $\omega$.
4. **Scaling lên lớn hơn:** Test tại 7B+ params, longer contexts (32K–128K), diverse corpora.
5. **Kết hợp với KV cache compression:** Quantization, eviction policies trên shared cache để giảm thêm memory.
6. **Cross-layer attention sharing:** Kết hợp memory sharing across recursions (LPT) với cross-layer KV sharing (CLA/YOCO).

### Kết hợp với phương pháp khác
- **Mixture-of-Recursions (Bae et al., 2025):** Adaptive token-level computation + LPT's shared memory.
- **State-Prediction Separation (Monea et al., 2026):** LPT tự nhiên tách state/prediction qua recursions thay vì streams — hai approaches có thể bổ sung nhau.
- **Speculative decoding:** Intermediate recursions có thể dùng cho draft tokens.

### Ứng dụng thực tế
- **Memory-constrained deployment:** Edge devices, mobile — H-LPT dùng ~0.2× context memory của STD.
- **High-throughput serving:** H-LPT fits 3.6–5× nhiều sequences per GPU, trực tiếp tăng batch size cho serving.
- **Quality improvement on budget:** Cùng parameter count, LPT/H-LPT đạt quality cao hơn STD, phù hợp khi memory cho weights bị giới hạn nhưng compute available.

## 12. Kết luận tổng quan

### Điểm mạnh
- **Ý tưởng đơn giản, hiệu quả bất ngờ:** Memory sharing là modification nhỏ (Equation 3) nhưng tạo ra cải thiện lớn và consistent trên mọi size/depth.
- **Phân tích rất sâu và thuyết phục:** 6 "Takeaway" messages, mỗi cái có evidence riêng — từ attention patterns, PCA representations, gradient analysis, đến ablation. Đây là một trong những phân tích mechanistic tốt nhất trong literature về looped Transformers.
- **Thực nghiệm rộng:** 3 sizes (150M–1B), 4 recursion counts (2,3,5,9), 7 baselines, normalization ablation (6 variants), window ablation, gradient detachment, seed variance tests.
- **Practical impact:** H-LPT tốt hơn STD về cả quality VÀ memory, đồng thời competitive về throughput — hiếm khi đạt cả 3 chiều.
- **Fair comparisons:** Không tune hyperparameters, cùng optimizer/data, parameter-matched.

### Điểm yếu
- **Compute overhead lớn:** 4.3–4.8× FLOPs tại 5 recursions. Không có FLOPs-matched comparison.
- **Scale giới hạn:** Chỉ đến 1B params, 4K context, 1 corpus, 1 tokenizer.
- **9 recursions unstable:** Benefit plateau hoặc reverse ở non-hybrid models.
- **No adaptive computation:** Mọi token cùng cost, dù dễ hay khó.
- **Latency trade-off rõ ràng:** Batch-1 chậm 2.3–5.7× so với STD.

### Giá trị đóng góp
Paper này thay đổi cách nhìn về memory sharing trong looped Transformers: từ "technique to save memory at a cost" thành "inductive bias that improves quality". Phát hiện gradient highway mechanism là insight quan trọng, giải thích tại sao shared memory giúp recursions learn different roles. Kết quả H-LPT đặc biệt ấn tượng — tốt hơn standard Transformer về quality với 76–79% ít memory — tạo ra một quality-memory frontier mới cho looped models. Đây là một contribution vững chắc cho cộng đồng nghiên cứu efficient Transformers và looped architectures.

### 13.3 Cơ chế "gradient highway" — những gì thực sự được chứng minh (Appendix D)
- Cách đo: lấy gradient của final loss tại 32 vị trí × 32 chuỗi validation; mỗi recursion có một bản copy tham số để tách đóng góp; tách đóng góp của recursion 1 thành đường hidden-state và đường shared-KV bằng detach (Eq. 5, chiếu lên gradient tổng).
- Tỉ lệ ‖g_KV‖/‖g_hidden‖ **tăng theo depth ngay từ khởi tạo** (Fig. 13), nên "càng nhiều recursion càng nhiều shared-KV" chỉ là hiệu ứng đếm số lần đọc, không tự nó chứng minh lợi ích.
- Thí nghiệm detach (Table 6) là bằng chứng nhân quả duy nhất: detach → PPL tăng ở mọi cấu hình so với LPT (S: 16.34 / 16.14 / 33.21 so với 15.73 / 15.28 / 14.91 ở R=2/3/5; M: 13.87 / 1,995 / 1,527 so với 12.91 / 12.55 / 12.33). M với R=3, 5 gần như không train (mức unigram). Lưu ý: ở S, R=2 và R=3, LPT-detached (16.34, 16.14) chỉ ngang hoặc tệ hơn nhẹ LT-final (16.05, 16.32) — detach gần như xóa lợi thế của LPT, đúng với giả thuyết.
- Tác giả tự thừa nhận: thí nghiệm **không phân biệt được** "đường gradient ngắn hơn" với "thay đổi scale/hướng gradient". Takeaway 6 vì thế mạnh hơn bằng chứng một chút.

### 13.4 Chi tiết phân tích representation
- PCA chỉ dùng **một chuỗi validation 4,096 token**, chỉ S-size, R=3, final loss (Fig. 6); Fig. 9–10 mở rộng sang S/M, R=3/5 và ω=4,096. Là bằng chứng định tính (không có metric tách cụm).
- Với ω = 4,096 (shared và local phủ cùng vị trí), cụm key vẫn tách được → shared key khác local key không chỉ vì khác vị trí/phạm vi.
- Kết luận phụ có giá trị: tính tương đồng key giữa các recursion (Bae et al., 2025 dùng để giải thích reuse không mất nhiều) **không phải điều kiện cần** — mô hình *học* cách phân vai.

### 13.5 Một lưu ý về ω = 0
Ở ω = 0, prediction recursion "không giữ lịch sử cục bộ" nhưng vẫn attend vào **entry hiện tại** của chính nó (và toàn bộ shared cache). Do đó nó vẫn là một phép so sánh có nghĩa (LPT > LT ở mọi ω), nhưng không phải "chỉ đọc shared memory" thuần túy.

### 13.6 Chi phí thực tế (Appendix F, H100 80GB, bf16, ctx 4,096)
- LPT fit 93–98% batch tối đa của STD; fit 2.0 / 2.9 / 4.7–4.8× số sequence của LT ở R=2/3/5.
- H-LPT giữ 20–27% cache của STD (cao hơn giá trị giải tích 3–17% do recurrent state fp32 + short-conv window), fit 3.6–5.0× STD và 1.8–3.8× LT².
- Ở **cùng batch**, LPT chậm hơn LT 3–8% (vẫn phải đọc cả shared cache lẫn window): shared cache tiết kiệm bộ nhớ, **không** tiết kiệm thời gian đọc (như Brandon et al. 2024 với cross-layer sharing). Peak throughput cao hơn nhờ batch lớn (+7–91%).
- Batch = 1: một bước decode của LT chậm 2.3 / 3.4 / 5.7× STD (R=2/3/5); LPT chậm hơn LT thêm 8–12%.
- H-LPT vs. STD (throughput tại batch tối đa): 2.1–2.2× (R=2), 1.4–1.5× (R=3), 0.8–0.9× (R=5).
- Đây là implementation nghiên cứu (PyTorch + FlexAttention + CUDA graphs), không phải serving engine tối ưu.

### 13.7 Chín recursions (Appendix E, Table 7)
Từ R=5 → 9: LPT +0.7 acc ở S, +0.2 ở M, **−1.7 ở L**; PPL cải thiện ở S nhưng xấu đi ở M, L. LT và PLT xấu đi ở mọi size. H-LPT tiếp tục tốt lên (+0.4 / +0.2 / +0.6 acc) và đạt PPL thấp nhất ở mọi size. Ouro cũng báo cáo loss spike ở 8 recursions → bất ổn ở depth cao là vấn đề chung của looped model, không chỉ của LT.

### 13.8 Điểm cần cẩn trọng khi dựa vào paper này
1. **So sánh "tiền tệ" không đồng nhất:** STD/DEEPSTD khớp tham số, không khớp FLOPs; LPT ở R=5 tốn 4.3–4.8× FLOPs decode so với STD. "H-LPT thắng STD" là thắng ở *cùng tham số*, không phải *cùng compute*.
2. **Hyperparameter không tune** (nanoGPT mặc định, kể cả LR/warmup cho LT ở depth): có lợi cho tính đồng nhất, nhưng LT final-loss sụp ở depth cao có thể một phần do LR/warmup (tác giả nói rõ là chưa thử).
3. **Chỉ 20–50B token, 1 corpus (FineWeb-Edu), GPT-2 tokenizer, ctx 4K**, benchmark zero-shot nhỏ (ARC-E, HellaSwag, PIQA, SciQ, LAMBADA) → chênh accuracy < 1 điểm nên xem là nhiễu.
4. **Chưa có long-context**: lợi ích bộ nhớ lớn nhất ở ctx dài nhưng chưa kiểm chứng; chất lượng khi ctx ≫ 4K (shared cache là nguồn thông tin duy nhất) chưa biết.
